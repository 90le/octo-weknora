# Octo 原生渠道能力清单

本清单按源码和自动化测试描述能力，不能替代部署版本、Bot 策略或客户端的实际验收。参考 [官方 OpenClaw 渠道](https://github.com/Mininglamp-OSS/openclaw-channel-octo) 和 [官方适配器目录](https://github.com/Mininglamp-OSS/octo-adapters)；实现保持 WeKnora 原生 Agent 与现有授权，不依赖 OpenClaw 运行时。

| 能力 | 当前实现和边界 |
| --- | --- |
| 连接 | 认证 WebSocket、心跳、重连和运行状态；相同 Bot 只应有一个有效接收端。 |
| 会话和授权 | 私聊显式 UID 与知识库授权；群及子区使用官方成员、区域和绑定校验，按用户隔离会话。 |
| 入站文本和引用 | 处理文本、富文本的纯文本、原生 @ 与回复引用；不把其他机器人的流式片段当成提问。 |
| 知识问答 | 复用原生 Agent、限定知识库与工具权限；消息中附加经过限定的来源说明。用户仍须在真实客户端核验引用呈现与访问。 |
| 图片及文件 | 支持平台单个图片、GIF 和文件消息，以及富文本中最多 4 张图片的有界下载与解析；所有附件总量最多 32 MiB，单张图片的视觉输入最多 8 MiB，CDN 主机有限制。授权私聊或明确触发的群消息收到语音、视频时给出不支持提示；这不是语音识别或视频理解。表情等不能视为已支持。 |
| 回答和可靠性 | 最终文本在发送前重验授权并写入消息账本；失败按既有幂等规则重试。模型不选择任意接收者。 |
| 状态 | 获准执行后发送原生已读回执和输入提示；提示失败不影响问答。 |
| 进度卡 | 服务端明确允许且广告兼容的 `ai.reasoning-process@0.4.1` 时，私聊及明确 @／回复 Bot 的授权群和子区可显示实时阶段。仅公开固定阶段摘要，不发布隐藏推理、参数或原始检索内容；最终答案仍是单独的可靠文本。 |
| 卡片兼容与恢复 | 不支持的配置或模板回退到原有文本；授权变化停止后续更新。已保存的进度卡 ID 随消息账本保留，终态恢复按最近 24 小时、每次最多 100 条扫描。网络故障发生在平台接收消息与本地记账之间时，仍须依靠平台的 `client_msg_no` 去重，不能声称绝对不会留下未完成卡片。 |
| 输出文件 | 知识业务报告可使用官方预签名上传并发送 HTML、Markdown、CSV；保留目标和范围检查，并非任意文件上传能力。 |
| 知识业务 | 已有知识预览、问题、联系人、本人确认和报告等专用工具；它们有独立业务授权，不等同于任意平台管理权限。 |
| 展示／交互卡 | 除进度模板外，模型自主发送展示卡、表单、按钮回调与服务端事件消费尚未实现。不得通过模型指令绕过授权调用原始接口。 |
| 逐字流式与其他宿主功能 | 尚未支持完整答案逐字输出、OpenClaw 专属插件工具或把其他 Agent 框架的会话与权限直接映射到 WeKnora。 |

验收应分别覆盖：私聊与授权群／子区；检索及引用；文本和允许的文件类型；卡片能力关闭或接口失败时的普通答案；授权撤销；应用重启；以及企业微信和 Web 回归。用户或获明确授权的测试人员在真实客户端完成消息收发，不以配置或模拟测试冒充真实验收。
